# План реализации: Ветки магий и целенаправленное изучение

> Статус: **выбор веток и целевое изучение реализованы**; HTTP/UI-сброс и магия 8-го круга остаются планами. Разделы 1–3 и 5 сохраняют первоначальный замысел; актуальный контракт и отличия реализации приведены в разделах 4 и 6.
> Связанные документы: [`docs/agents/magic-system.md`](../agents/magic-system.md), [`server/arena/BranchService.ts`](../../server/arena/BranchService.ts), [`server/arena/MagicService.ts`](../../server/arena/MagicService.ts), [`shared/actions/branches.ts`](../../shared/actions/branches.ts)

### Миграция данных

Перед запуском новой версии остановите сервер и сделайте резервную копию MongoDB. Затем из каталога `server` выполните `MONGO='<mongodb-uri>' bun run migrate-branches`. Скрипт переносит `magicBranches` в `branches`, сохраняя существующие выбранные ветки, и удаляет старое поле. Документы с некорректным типом поля пропускаются; их количество выводится для ручной проверки.

Скрипт также очищает `magics`, `skills` и `passiveSkills` и устанавливает `bonus = Math.round(exp / 100)` для каждого персонажа с корректным неотрицательным опытом. Округление общей суммы опыта может отличаться от суммы округлений отдельных начислений; бонусы из других источников не сохраняются. Сброс способностей для персонажей с некорректным опытом пропускается и выводится в предупреждении. **Не запускайте скрипт повторно после возобновления игры:** он снова удалит изученные способности и перезапишет бонусы.

## 1. Цели и мотивация

1. **Отказ от рандома («всё подряд»)**:
   - **Историческая мотивация:** прежняя схема «Изучить круг N» с шансом 60% и случайным заклинанием заменена на `MagicService.learnSpecificMagic`; метода `MagicService.learnMagic` теперь нет.
   - Поскольку пул заклинаний небольшой (1–2 заклинания на круг внутри ветки), случайный выбор лишен смысла и раздражает игрока промахами.
2. **Формирование билдов (Специализация)**:
   - Игрок может развивать персонажа максимум в **1–2 ветки** (из 3 доступных классу).
   - Третья ветка блокируется, стимулируя разнообразие билдов (например: Стихийный маг, Маг крови/некромант, Маг контроля/защиты; Хил-жрец, Защитник-жрец, Инквизитор-жрец).
3. **Целенаправленное изучение (Targeted Learning)**:
   - Игрок видит дерево/список заклинаний своей ветки и целенаправленно вкладывает очки `bonus` в конкретные магии со **100% шансом успеха**.

## 3. 8-й круг: Истинная магия подклассов (Перспектива / Улучшение класса)

**Проект, не текущая механика.** 8-й круг задуман как **Истинная магия** («Prestige Magic») для улучшенных классов; указанные ниже заклинания и проверка подкласса при изучении не реализованы. Подробная документация: [`docs/agents/subclasses.md`](../agents/subclasses.md).

### 3.1. Магические подклассы и их заклинания

| Подкласс | Комбинация | Код | Заклинание | Механика |
|---|---|---|---|---|
| **Епископ** | Жрец + Жрец (`p+p`) | `8ppa`<br>`8ppb` | **Святость**<br>**Святой обряд** | Полная неуязвимость к физ. атакам и прямой магии (спадает при атаке)<br>Карающий святой урон |
| **Отшельник** | Жрец + Маг (`p+m`) | `8pma`<br>`8pmb` | **Ураганный ветер**<br>**Подмена** | Урон ветром со срезом атаки цели на 10–30<br>Обманная магия подмены цели |
| **Хаотик** | Маг + Жрец (`m+p`) | `8mpa`<br>`8mpb` | **Апокалипсис**<br>**Армагеддон** | Комбо: общие глюки + анафема + неснимаемый холод на 5 ходов<br>Глобальный взрыв по всей арене |
| **Архимаг** | Маг + Маг (`m+m`) | `8mma`<br>`8mmb` | **Мозговая атака**<br>**Ледяной шторм** | Тяжелейший ментальный урон разуму цели<br>Ледяной вихрь по врагам |
| **Аббат** | Воин + Жрец (`w+p`) | `8wpa`<br>`8wpb` | **Жажда крови**<br>**Клонирование** | Резкое увеличение атаки цели<br>Создание своего двойника в бою |
| **Элементалист** | Воин + Маг (`w+m`) | `8wma` | **Ярость** | Увеличение атакующего урона яростью стихий |
| **Друид** | Лучник + Маг (`l+m`) | `8lma` | **Святая защита** | Щит святости и периодическое исцеление |
| **Монах** | Лучник + Жрец (`l+p`) | `8lpa`<br>`8lpb` | **Слабость**<br>**Кровавая аура** | Сильное ослабление атаки цели<br>Аура крови |

### 3.2. Как 8-й круг вписывается в систему веток

1. **Предлагается вне лимита 2 веток**: 8-й круг не должен расходовать слоты базовых веток.
2. **Предлагается привязка к подклассу, а не к ветке**: доступ к магии 8-го круга должен даваться при наличии соответствующего улучшенного подкласса персонажа.
3. **Архитектурный задел (Future-proofing)**:
   - В `shared/actions` предусмотреть для `Magic` опциональные метаданные:
     ```typescript
     subclassReq?: SubclassId; // например, 'archmage' | 'bishop' | 'chaotic' | ...
     profComboReq?: [CharacterClass, CharacterClass]; // ['m', 'm'], ['m', 'p']...
     ```
   - В модель `Character` предусмотреть возможность хранения подкласса:
     ```typescript
     subclass?: string; // идентификатор улучшенного подкласса
     ```
   - В `MagicService` заложить проверку требований к подклассу при `lvl === 8`.

## 4. Правила выбора веток и прокачки (Вариант А)

1. **Лимит веток**: Персонаж может иметь **максимум 2 активные ветки** (`branches`).
2. **Слоты веток**:
   - **Слот 1 (Основная ветка)**: Доступен сразу (с 1-го уровня персонажа). Игрок выбирает одну из трех веток своего класса.
   - **Слот 2 (Вторая ветка)**: Открывается при достижении **10-го уровня персонажа** (`SECOND_BRANCH_MIN_CHAR_LVL = 10` в `shared/actions/branches.ts`). Историческое требование 5-го уровня больше не действует.
   - **Слот 3 (Третья ветка)**: Остается заблокированным. Заклинания третьей ветки изучить нельзя.
3. **Целенаправленная прокачка заклинаний**:
   - Игрок кликает на конкретное заклинание из своих активных веток.
   - Проверяются условия:
     - Заклинание принадлежит классу персонажа и хотя бы одной из выбранных веток; заклинание без веток изучить нельзя.
     - Уровень персонажа достаточен для круга заклинания: `canLearnMagic(character.lvl, magic.lvl)`.
     - Текущий уровень заклинания меньше 3: `(character.magics[magic.name] ?? 0) < 3`.
     - У персонажа хватает очков `bonus`: `character.bonus >= getLearnMagicCost(magic.lvl)`.
   - При подтверждении списываются очки `bonus`, уровень магии повышается на +1 со **100% шансом**.
4. **Сброс веток (Респек)**:
   - `MagicService.resetMagics` существует, но кнопки и HTTP-маршрута нет.
   - Метод очищает магические записи в `branches`, обнуляет `character.magics` и возвращает `getLearnMagicCost(круг) * ранг` бонусов за каждое известное изученное заклинание; физические ветки не затрагиваются.

## 5. Архитектура изменений

Исходный проект ниже фиксирует первоначальные требования (порог второго слота и путь параметра API скорректированы); актуальные типы, владельцы методов и HTTP/UI-контракты перечислены в разделе 6. Псевдокод и эскизы экранов в этом разделе не следует использовать как описание действующего API.

### 5.1. Слой Shared (`packages/shared` или `shared/`)

1. **Типы веток (`shared/actions/branches.ts`)**:
   ```typescript
   export type MageBranch = 'elements' | 'darkness' | 'arcana';
   export type PriestBranch = 'holy' | 'protection' | 'inquisition';
   export type MagicBranchId = MageBranch | PriestBranch;

   // Задел под подклассы 8-го круга (улучшение класса):
   export type SubclassId =
     | 'bishop'       // p+p Епископ
     | 'hermit'       // p+m Отшельник
     | 'chaotic'      // m+p Хаотик
     | 'archmage'     // m+m Архимаг
     | 'abbot'        // w+p Аббат
     | 'elementalist' // w+m Элементалист
     | 'druid'        // l+m Друид
     | 'monk';        // l+p Монах

   export interface MagicBranchMeta {
     id: MagicBranchId;
     name: string;
     description: string;
     icon: string;
     prof: 'm' | 'p';
   }

   export const SECOND_BRANCH_MIN_CHAR_LVL = 10;
   ```
2. **Метаданные заклинания и гибридные школы**:
   - Поле `branches?: MagicBranchId[]` прямо в параметрах магии (`MagicArgs` в `server/arena/Constuructors/MagicConstructor.ts` и в конкретных файлах `server/arena/magics/`).
   - Заклинание может принадлежать **сразу нескольким школам (гибридное)**. Персонажу достаточно иметь **хотя бы одну** из этих веток, чтобы выучить заклинание:
     - `dispel`: `['protection', 'inquisition']` (снятие дебаффов со своих / снятие баффов с врагов)
     - `secondLife`: `['holy', 'protection']` (святое воскрешение / защитный бафф спасения от смерти)
     - `exorcism`: `['protection', 'inquisition']` (очищение соратников / изгнание скверны)
     - `lightHeal`: `['holy', 'protection']` для Жреца; `['arcana']` для Мага
     - `bodySpirit`: `['inquisition', 'holy']` (карающее выжигание HP врага + пополнение маны)
     - `frostTouch`: `['elements', 'darkness']` (стихийный урон холодом + периодический DoT увядания)
     - `blight`: `['darkness', 'arcana']` (некротический срез HP + ментальное истощение)
     - `vampirism`: `['darkness', 'arcana']` (высасывание здоровья + перенос энергии)
   - В интерфейсе `Magic` возвращается `branches: MagicBranchId[]` и `branch: MagicBranchId`.

### 5.2. Слой Базы Данных (`server/models/character.ts`)

- Добавить в схему `Character` поле:
  ```typescript
  branches: {
    type: [String],
    default: [],
  }
  ```
- Перед развертыванием на существующей базе выполнить `cd server && bun run migrate-branches`: одноразовая миграция переносит `magicBranches` в `branches` без постоянного слоя совместимости.

### 5.3. Серверная бизнес-логика (первоначальный эскиз)

- Добавить методы:
  - `selectBranch(character: CharacterService, branchId: MagicBranchId)` (теперь в `BranchService`):
    - Проверка принадлежности ветки классу персонажа.
    - Проверка лимита: макс 2 ветки. Если выбирается 2-я — проверка уровня персонажа `>= SECOND_BRANCH_MIN_CHAR_LVL`.
  - `learnSpecificMagic(character: CharacterService, magicName: string)`:
    - Проверка наличия заклинания в `arena.magics`.
    - Проверка принадлежности ветке из `character.branches` (проверка подкласса для 8-го круга пока не реализована).
    - Проверка `canLearnMagic(character.lvl, magic.lvl)`.
    - Проверка `(character.magics[magicName] ?? 0) < MAX_MAGIC_LVL`.
    - Списание `bonus` (`getLearnMagicCost(magic.lvl)`).
    - Вызов `character.learnMagic(magicName, currentLvl + 1)`.
    - 100% шанс (без `learnChance()`).
  - `resetMagics(character: CharacterService)`:
    - Подсчет всех потраченных очков `bonus`.
    - Очистка `character.magics = {}`.
    - Очистка только магических записей в `character.branches`.
    - Возврат очков `bonus`.

### 5.4. HTTP API (первоначальный эскиз)

- `POST /branches` — выбор ветки (body: `{ branch: BranchKey }`).
- `POST /magic/learn/:name` — изучение конкретного заклинания.
- `POST /magic/reset` — планировался, но не опубликован; сброс магий и магических веток с возвратом бонусов.
- `GET /branches` — статус веток персонажа (выбранные, доступные для выбора, заблокированные).

### 5.5. Клиентский интерфейс (первоначальный эскиз)

- **Экран без выбранной ветки**:
  - Приветственный выбор 1-й специализации с описанием и иконками 3 веток.
- **Древовидный / карточный экран магий**:
  - Вкладки или аккордеоны выбранных веток.
  - Список заклинаний, сгруппированный по кругам (1..7).
  - На каждом заклинании:
    - Название, иконка, описание, стоимость маны.
    - Текущий уровень (звездочки / индикатор `1/3`, `2/3`, `3/3`).
    - Кнопка «Улучшить» с точной ценой в `bonus💡` (активна только при выполнении условий).
  - Слот 2-й ветки:
    - Если `lvl < 10`: заблокирован с плашкой «Откроется на 10-м уровне».
    - Если `lvl >= 10` и не выбрана: кнопка «Выбрать вторую специализацию».
  - Заблокированная 3-я ветка:
    - Отображается серым/замочком с подсказкой о лимите специализации.
  - Кнопка «Сброс магий» внизу экрана с модальным окном подтверждения.

   - Полностью удален промежуточный словарь `MAGIC_TO_BRANCHES`: каждое заклинание самодостаточно декларирует свои специализации.
2. [x] **Шаг 2 (Server Business Logic)**:
   - В `CharacterService` добавлены геттер `branches`, методы `setBranches`, `resetMagics`, сохранение в базу и выгрузка клиенту.
   - В `CharacterResources` добавлена поддержка добавления `bonus` для корректного 100% возврата очков при респеке.
   - В `MagicService` реализованы:
     - `learnSpecificMagic(character, magicName)` — детерминированное изучение (100% шанс успеха, стоимость `getLearnMagicCost(magic.lvl) = magic.lvl ** 2 * 10` за каждый ранг, проверка класса, выбранной ветки и круга магии, лимит 3 ранга).
     - `resetMagics(character)` — сброс изученных магий и только магических веток с возвратом бонусов за известные заклинания; метод не опубликован через HTTP.

   - В `BranchService` реализованы `selectBranch(character, branchKey)` — выбор специализации с проверкой существования ветки, класса, повторного выбора, лимита в 2 ветки и требования 10-го уровня для 2-го слота; `getBranchesInfo(character)` возвращает `{ branches: [...] }` с чистым списком метаданных веток текущего класса (`BranchMeta[]`). Статусы карточек (`isSelected`, `lockReason`) вычисляются реактивно на клиенте на основе `character().branches`. `hasSelectedBranch` используется при изучении активных и пассивных физических умений; отсутствие веток у умения не блокирует изучение.
   - **Единое дерево способностей (`AbilityTreeService`)**: реализован сервис `AbilityTreeService.getTree(character)`, который объединяет магии (`MagicService`), активные умения (`SkillService`) и пассивки (`PassiveSkillService.getPassiveSkillListByClass`) всех классов в структурированное дерево `Record<CharacterClass, { class, branches: [...] }>`. Каждая способность декорируется унифицированными свойствами `rank`, `maxRank`, `nextCost`, `requiredLevel`, `canLearn`, `lockReason`.
   - **Гибридные заклинания (мульти-школы)**: заклинания могут принадлежать нескольким школам (`dispel`, `secondLife`, `exorcism`, `lightHeal`, `bodySpirit`, `frostTouch`, `blight`, `vampirism`, `mediumAura`). Для изучения достаточно иметь хотя бы одну из школ заклинания.
