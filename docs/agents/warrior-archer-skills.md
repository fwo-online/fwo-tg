### 2.2. Мастерство оружия (Weapon Mastery)

Их боевые эффекты и сохранённые уровни продолжают работать, но записи скрыты из списка `GET /passiveSkill` (в том числе при запросе через `ids`) и экрана изучения. Каждый навык имеет **6 уровней прокачки** со стоимостью:
`bonusCost: [30, 60, 90, 120, 150, 180]` (суммарно 630 бонусов).

## 3. Детальный разбор активных умений

### 3.1. Парирование (`parry`)
- **Класс**: Воин (`w: 1`).
- **Порядок в раунде**: Стадия `parry` (выполняется до атаки).
- **Стоимость энергии**: `[8, 9, 10, 11, 12, 13] EN`.
- **Шанс успеха**: `[70, 75, 80, 85, 90, 95]%`.
- **Множитель ловкости (`effect`)**: `[1.1, 1.2, 1.3, 1.4, 1.5, 1.6]`.
- **Формула**:
  ```typescript
  value = initiator.dex * effect;
  // При получении физ. урона холодным оружием (thrust, cut, chop, stun):
  affect.value -= enemy.dex;
  if (affect.value > 0) {
    // Удар успешно парирован! Атака противника прерывается CastError
  }
  ```

### 3.2. Блок щитом (`shieldBlock`)
- **Класс**: Воин (`w: 4`).
- **Требование**: Экипированный щит в слоте `offHand`.
- **Стоимость энергии**: `[8, 9, 10, 11, 12, 13] EN`.
- **Емкость блока**:
  ```typescript
  shieldCapacity = (0.3 * str + 0.7 * con + 0.25 * shield.defence) * effect;
  ```
- **Особенности**:
  - Пока действует щит, персонаж получает бонус к **магической защите** (`magic.defence += shieldCapacity`).
  - Каждый удар врага истощает прочность блока на `(0.7 * enemy.str + 0.3 * enemy.con) * proc`.
  - Если емкость блока исчерпана — блок спадает.

### 3.3. Увёртка (`dodge`)
- **Класс**: Лучник (`l: 2`).
- **Стоимость энергии**: `[10, 12, 14, 16, 18, 20] EN`.
- **Шанс применения**: `[75, 80, 85, 90, 95, 99]%`.
- **Формула шанса уворота от атаки**:
  ```typescript
  dodgeValue = effect * initiator.dex;
  dodgeFactor = Math.round(dodgeValue / enemy.dex);
  chance = Math.round(Math.sqrt(dodgeFactor) + 10 * dodgeFactor + 5);
  // При chance > d100 атака противника срывается!
  ```
- Защищает от любого оружия, кроме безоружного и специфической магии.

### 3.4. Обезоруживание (`disarm`)
- **Классы**: Воин (`w: 3`), Лучник (`l: 5`).
- **Тип заказа**: `OrderType.Enemy` (направлено на конкретного противника).
- **Стоимость энергии**: `[12, 13, 14, 15, 16, 17] EN`.
- **Формула успеха**:
  ```typescript
  if (initiator.dex * effect >= target.dex) {
    // Цель обезоружена: ее физ. атака оружием в этом раунде отменяется
  }
  ```

### 3.5. Берсерк (`berserk`)
- **Класс**: Воин (`w: 4`).
- **Стоимость энергии**: `[8, 9, 10, 11, 12, 13] EN`.

### 3.8. Выстрел в колено (`cripplingShot`)
- **Класс**: Лучник (`l: 2`), ветка `marksman`.
- **Тип заказа**: `OrderType.Self` (селф-бафф на следующий выстрел).
- **Требование**: Оружие дальнего боя (`range`).
- **Стоимость энергии**: `[12, 14, 16] EN`.
- **Шанс успеха**: `[80, 85, 90]%`.
- **Эффект снижения ловкости**: `[25, 35, 45]%`.
- **Цитата**: *«Когда-то и меня вела дорога приключений, а потом мне прострелили колено...»*
- **Механика**:
  - В раунде вешает на лучника эффект с хуками `onBeforeDamageDeal` и `onDamageDealt`.
  - `onBeforeDamageDeal`: сбивает текущую увёртку цели (`removeEffectsByAction('dodge')`).
  - `onDamageDealt`: при попадании физ. атакой дальнего боя сразу снижает ловкость цели (`this.onCast(target, value)`) и вешает долгий эффект `addLongEffect` на 2 раунда:
    - `onCast()`: вызывает `cripplingShot.onCast(target, this.value)` для повторного снижения ловкости в начале каждого раунда (после межраундового сброса статов в `StatsService.refresh()`).
    - `onBeforeAction(ctx, action, affect)`: если цель пытается применить «Увёртку» (`dodge`), формирует контекст с инициатором выстрела и целью и выбрасывает `new CastError(this.getSuccessResult(this.context))`. Благодаря этому уворот цели срывается, а в боевой лог записывается точная причина: `_🎯 Выстрел в колено_ *Игрок 1*: 📖0`.

- **Шанс успеха**: `[80, 85, 90]%`.
- **Урон второй стрелы**: `[60, 75, 90]%`.
- **Механика**:
  - В раунде вешает на лучника эффект `onDamageDealt`.

  - Клонирует базовое действие (`action.cloneAction()`), масштабирует долю хода стрелка (`proc * (value / 100)`), ставит защиту от рекурсии (`this.lock = true`) и совершает дополнительный выстрел во вторую цель (`actionClone.cast(...)`).

- **Класс**: Воин (`w: 3`), Лучник (`l: 6`), ветки `guardian` и `scout`.
- **Тип заказа**: `OrderType.TeamExceptSelf` (на выбранного союзника).
- **Стоимость энергии**: `[10, 11, 12, 13, 14, 15] EN`.
- **Шанс успеха**: `[70, 75, 80, 85, 90, 95]%`.
- **Доля хода (proc)**: `15%`.
- **Стоимость изучения (`bonusCost`)**: `[10, 20, 30, 40, 60, 80]` бонусов.
- **Параметр `effect`**: `[1, 1, 1, 1, 1, 1]` (6 рангов), записывается в `affect.value` и проверяется как признак активности (truthy). Это **не заряд**: значение не уменьшается, эффект при перехвате не удаляется.
- **Механика**: Прикрывает выбранного союзника от **всех физических атак** до конца текущего раунда (`refresh()`), без счётчика зарядов. Хук `onBeforeDamageRecieve` перенаправляет действие типа `phys` на `affect.initiator` через `ctx.overrideTarget`. Это не гарантированный блок: урон принимает спасатель, отдельного процентного снижения нет. Проверок положительного урона, жизни спасателя или совпадения цели в текущем обработчике нет; погибший спасатель тоже может перехватить удар. Другие типы действий, в том числе магические, не перехватываются. Повторное применение заменяет прежнее «Спасение» на союзнике.
- **Цепочки и циклы перенаправлений**: Общий генератор `PlayerAffects` при смене коллекции `ctx.target.affects` после receive-хука переключается на полный снимок новой коллекции с первой стадии. Уже обработанные и удалённые экземпляры пропускаются; добавленные видны лишь следующему снимку. Возврат к игроку разрешён, следующее попадание получает новый Set без расходования «Спасений». Подробнее: [алгоритм обхода и ограничения](effects-system.md#перенаправление-цели-и-ограничения). Урон не перезапускается: если удар не отменён, сопротивления, HP, проверка смерти и `onDamageReceived` единожды используют фактическую `ctx.target`.
- **Гарантия завершения**: При конечном числе экземпляров эффектов за dispatch и завершающихся хуках локальный Set предотвращает повторное выполнение экземпляров и зацикливание на них. Он не предотвращает бесконечное создание новых эффектов-перенаправителей.
- **Охват хука**: Только атаки через `EffectService.damage`. Вторичный урон через `rawDamage` (например, рикошет и размашистый удар) по архитектуре не вызывает receive-хуки и не перехватывается.
- **Порядок**: Общий стабильный порядок всех аффектов задаёт `config.stages`, включая длительные эффекты прошлых раундов. `help` стоит после `bodySpirit`, перед группой `smallAura`…`magicWall` и последующими блоками/уклонениями. Теперь `help` также раньше `paralysis`: паралич этого раунда не отменяет уже наложенное прикрытие, но мешает последующим действиям. `sleep` по-прежнему раньше `help`.
- **Лог и опыт**: Активация сообщает о прикрытии союзника и даёт 20 опыта. Каждый выполненный перехват добавляет запись в аффекты удара с `actionType: 'passive'` и собственным `msg` («перехватил атаку по…»), без `📖0` и без выставления `event`. Запись сохраняется и при последующем блоке, выводится после причины отмены. За перехват опыта нет; отдельный массив `FailArgs.affects` не участвует в повторном начислении опыта.

## 5. Ветки специализации и смешанные деревья (Активные + Пассивные)

По аналогии с магической системой, каждый физический класс получает **3 ветки специализации**. Игрок выбирает **максимум 2 ветки** (1-я доступна сразу, 2-я с 10-го уровня по `SECOND_BRANCH_MIN_CHAR_LVL`); третья блокируется. Лимит и слоты общие для всех веток в `character.branches`, но `BranchService.selectBranch` разрешает выбирать только ветки текущего класса.

**Состояние реализации:** выбор работает через `BranchService` и `GET/POST /branches` (`server/server/branches.ts`). `GET /branches` отдаёт `{ branches: [...] }` с метаданными веток своего класса; статус доступности и блокировки (`isSelected`, `lockReason`) вычисляется на клиенте на основе реактивного `character().branches`. `POST` принимает `{ "branch": "guardian" }` (валидируется через `v.picklist(keys(BRANCHES))`) и возвращает `{ branches, selectedBranch }`. Кроме того, эндпоинт `GET /branches/tree` через `AbilityTreeService.getTree(character)` формирует единое дерево всех способностей (магии, активные умения, пассивки) по классам и веткам, рассчитывая для каждой способности условия изучения и стоимость.

Активные умения и пассивки с указанными `branches` изучаются/улучшаются при наличии хотя бы одной выбранной ветки того же класса (`BranchService.hasSelectedBranch`). Навыки без ветки, в том числе общие оружейные мастерства, доступны без выбора; ранее изученные умения остаются доступны в бою, но для улучшения веточного умения нужна его ветка. У воина пока отмечены ветками только `parry`, `shieldBlock`, `berserk`, `disarm`, `help`, `weightyArgument` и `shakeUp`; часть прочих талантов уже существует без привязки к ветке, а новые способности в деревьях ниже — проект, не готовая реализация, за исключением «Веского аргумента» (`weightyArgument`), «Встряски» (`shakeUp`) и общего эффекта «Контузия» (`concussion`), которые уже реализованы. Перед развертыванием на существующей базе выполните `cd server && bun run migrate-branches`, чтобы перенести сохраненные магические ветки из старого поля.

Страницы активных и пассивных умений используют общий `BranchPicker.svelte` вместе со страницей магий; также доступен объединённый экран `/character/abilities` с карточками `AbilityCard`, единым раннером `learnAbility` и подсветкой рангов через `RankedValues`. Выбор веток отправляет `POST /branches` и инвалидирует `app:branches-info` и `app:character`; счётчик «Ветки (N/2)» использует `character().branches`.

В каждой ветке находятся как **активные умения** (требуют заказа хода и тратят энергию `en`), так и **пассивные таланты** (работают автоматически через хуки боя).

### 5.2. Ветки Воина (`w`)

В проекте оружейные пассивки привязываются к веткам: Ярость / Варвар (`berserker`) — `chop` (топоры/секиры), Дуэлянт (`duelist`) — `cut` (мечи/кинжалы), Оплот (`guardian`) — `stun` (молоты/булавы). Баланс пассивок выбранных веток должен поощрять профильное оружие, в том числе в смешанных сборках двух веток. Отдельную новую систему владения или прогрессии оружия не вводим. Возможный перенос этих пассивок на предметы — лишь будущее направление, а не утверждённая или реализованная механика.

#### 1. 🛡️ Оплот / Танк (`guardian`) — Щиты, защита соратников, таунт, стан
- ⚡ **Блок щитом** (`shieldBlock`): активный блок: емкость блока щита поглощает удары, временно повышает магзащиту (уже в коде).
- ⚡ **Спасение** (`help`): перенаправляет все физические атаки по выбранному союзнику на Воина до конца раунда, без счётчика зарядов. Не провокация врага; [при повторных перенаправлениях](effects-system.md#перенаправление-цели-и-ограничения) обход переключается на полный снимок новой коллекции аффектов цели, пропуская уже обработанные и удалённые экземпляры.
- ⚡ **Удар щитом** (`shieldBash`): *активное умение контроля (проект, не реализовано)*: с шансом 50–75% оглушает цель (`stun`) на 1 ход. Собственного урона не наносит.
- 🛡️ **Веский аргумент** (`weightyArgument`): *пассивный талант, реализован*. Физическое попадание владельца дробящим оружием типа `stun` (молоты/булавы/дубины), включая сплеш, фактически нанесшее положительный урон, с шансом 10/15/20% накладывает на фактическую цель попадания эффект «Контузия» (`concussion`) силой 10/20/25% на 2 раунда, включая текущий. Если у фактической цели уже есть «Контузия», пассивка пропускает наложение независимо от силы и источника эффекта, без броска шанса, продления или замены.
- 🛡️ **Несокрушимость** (`unyielding`): *пассивный талант (проект, не реализован)*. Пока текущий HP строго ниже 30% максимального, весь получаемый урон снижается на 10–25% в зависимости от уровня таланта. При HP ровно 30% максимума или выше не действует.

**Реализованная механика «Веского аргумента» и «Контузии»:**
- Изучение: Воин с 1-го уровня, ветка `guardian`; **3 ранга**, `bonusCost: [10, 20, 30]`. Шанс по рангам: `[10, 15, 20]%`, сила (`power`): `[10, 20, 25]%`. Пассивка доступна в каталоге и дереве способностей.
- Эффект умножает только боевые `inRound`-значения `phys.attack` и `magic.attack` цели на `1 - power / 100` (то есть `0.90 / 0.80 / 0.75`). Это изменение характеристик, **не прямой множитель итогового урона**; исходные статы и документ персонажа не изменяются.
- Физический сплеш и вторичные попадания через `rawDamage` могут запускать пассивку при оружии владельца типа `stun` и положительном фактически нанесённом уроне, с теми же проверками изученного ранга и шанса. Промах, полный блок, нулевой урон и DoT не запускают пассивку; кровотечение отсекается типом действия. При перенаправлении «Спасением» эффект получает **фактическая цель**, принявшая попадание.
- «Контузия» наследует `LongMagic`, но **запись регистрирует источник** — «Веский аргумент» или «Встряска»: `target.affects.addLongEffect` получает `action: concussion.name`, `initiator`, сохранённую силу в `value`, `duration: 2` и callback `onCast`. Источник сразу вызывает `onCast` новой записи, который выполняет `concussion.castLongEffect(initiator, target, game, affect)`. Сам `concussion.cast` только применяет снижение статов и пишет лог; он **не регистрирует и не продлевает** эффект.
- Это **не `stun` и не ограничение действий**. Каждое отдельное наложение источником создаёт независимую двухраундовую запись и сразу снова умножает обе атаки (например, два наложения по 10%: `100 → 90 → 81`). Только «Веский аргумент» проверяет наличие «Контузии» у фактической цели **до проверки шанса** и пропускает наложение без продления при любом уже существующем эффекте. Это правило пассивки не распространяется на другие источники, в том числе на «Встряску».
- **Текущий раунд входит в эти 2 раунда.** В раунде N эффект применяется сразу с `duration: 2`; после `PlayerService.reset()` статы восстановлены, запись остаётся с `duration: 1`. В ранней стадии `concussion` раунда N+1 каждая запись один раз повторно применяет сохранённую силу без новой регистрации, магических бросков, расходов или масштабирования от магии/`proc`. В конце N+1 статы снова восстанавливаются, а `affects.refresh()` удаляет записи с нулевой длительностью; пассивка сохраняется и после истечения эффекта может сработать вновь.
- `WithLongEffect.castLongEffect` клонирует действие, копирует оставшуюся `duration` и передаёт **весь `affect` четвёртым аргументом** в `clone.cast(initiator, target, game, affect)`. Специальный `concussion.cast` берёт силу из `affect.value`, обходит обычные магические проверки/расходы/масштабирование и явно вызывает `game.recordOrderResult(this.getSuccessResult())` даже при `isAffect = true`. Поэтому в логе видны `⏳2 Контузия` при наложении и `⏳1 Контузия` в следующем раунде.
- Реализации: [`weightyArgument.ts`](../../server/arena/passiveSkills/weightyArgument.ts), [`shakeUp.ts`](../../server/arena/skills/shakeUp.ts) и переиспользуемый [`concussion.ts`](../../server/arena/effects/concussion.ts); подробнее — [переприменение стат-дебаффов через `onCast`](effects-system.md#переприменение-дебаффов-характеристик-в-раундах-oncast). Это не пассивка «Сотрясение» (`consussion`): она по-прежнему накладывает настоящее оглушение.

#### 2. 🪓 Ярость / Варвар (`berserker`) — Разрушительный урон, сплеш, жертва защитой
- ⚡ **Берсерк** (`berserk`): активная стойка: резкое повышение максимального урона ценой снижения защиты (уже в коде).
- ⚡ **Кровожадность**: *активное умение (проект, не реализовано)*: до конца текущего раунда восстанавливает HP в размере 10–25% фактически нанесённого прямыми атаками урона, в зависимости от уровня умения. Не лечит от DoT, вторичного урона или убийств.
- ⚡ **Встряска** (`shakeUp`): *активное умение, реализовано*, заменяет проектный «Угрожающий рёв». Воин, ветка `berserker`, с 1-го уровня; **3 ранга**, `bonusCost: [10, 20, 30]`, расход EN по рангам **`[10, 12, 14]`**, шанс успешной подготовки **`[75, 85, 95]%`**, сила Контузии **`[10, 15, 25]%`**, `proc: 25%`. Заказ на себя (`OrderType.Self`) проходит стандартный `SkillConstructor`: EN списывается **до броска шанса**, поэтому при неудачной подготовке расход сохраняется. При успехе подготовка действует до конца **текущего раунда**; ранняя стадия позволяет подготовиться и атаковать в одном раунде. Первое физическое попадание с положительным фактически нанесённым уроном, включая сплеш/`rawDamage`, расходует подготовку и гарантированно, **без дополнительного броска**, накладывает на **одну фактическую цель** после перенаправлений общую «Контузию» на фиксированные **2 раунда, включая раунд попадания**. Подготовка снимается до наложения эффекта; промах, полный блок и нулевой урон её не расходуют, но конец раунда удаляет неиспользованную подготовку. Магический урон и DoT не активируют её. Нет собственного или бонусного урона, гарантии попадания, дополнительного расхода EN при попадании либо оружейного условия `stun`. Уже имеющаяся «Контузия» не мешает новому наложению: источник добавляет отдельную запись с обычным повторным перемножением характеристик.
- 🛡️ **Размашистый удар** (`sweepingBlow`): *пассивный талант*. При атаках рубящим оружием (`chop`, топоры/секиры) с шансом 10/15/20% наносит 15/20/25% урона основной атаки одной случайной дополнительной вражеской цели.
- 🛡️ **Отчаянная ярость** (`desperateFury`): *пассивный талант (проект)*. Пока текущий HP строго ниже 30% максимального, наносимый урон увеличивается на 10–25% в зависимости от уровня таланта. При HP ровно 30% максимума или выше не действует. Не связан с убийствами, не лечит и не восстанавливает энергию.

#### 3. 🗡️ Дуэлянт / Ассасин (`duelist`) — Фехтование, парирование, обезоруживание, кровотечения
- ⚡ **Парирование** (`parry`): активный тактический прием: парирование атак холодного оружия ближнего боя (уже в коде).
- ⚡ **Обезоруживание** (`disarm`): активный тактический прием: выбивает оружие цели при сравнении ловкости (уже в коде).
- ⚡ **Точный выпад** (`vitalStrike`): *проект, не реализовано*. Активная подготовка, усиливающая следующую атаку, а не самостоятельный удар. Следующая атака игнорирует 50% защиты цели; по оглушённой или обезоруженной цели её критический множитель — ×1,75.
- 🛡️ **Рассечение** (`lacerate`): *пассивный талант*. Атаки режущим оружием с шансом 20–35% накладывают сильное кровотечение `bleeding` на 3 раунда.
- 🛡️ **Контрудар** (`riposte`): *пассивный талант (проект, не реализован)*. После успешного парирования воин немедленно совершает бесплатную полноценную ответную атаку по атаковавшему врагу: со стандартными проверками попадания/промаха, уклонения, парирования, блока и применимыми эффектами ([пайплайн урона](effects-system.md#effectservice--пайплайн-урона)). Это не гарантированное попадание и не прямой урон через `rawDamage`.

## 6. Механика изучения и респека

1. **Дерево ветки в UI**:
   - На страницах активных и пассивных умений есть режимы **«Изучение»** (список доступных своему классу умений и их стоимость в `bonus` 💡) и **«Ветки (N/2)»** (общий `BranchPicker`, выбор второй ветки с 10-го уровня).
   - Уже изученные умения видны в списке даже при отсутствии соответствующей выбранной ветки; повторное изучение без неё блокируется сервером.
2. **Стоимость**:
   - Для каждого умения цена следующего ранга берётся из его `bonusCost[текущий ранг]`; лимит рангов равен длине `bonusCost` и зависит от умения (не общий лимит в 3 ранга).
   - **Контракт EN и рангов:** каталожный `Skill.cost: number[]` содержит расходы всех рангов через `SkillService.toObject`, `/skill/:id`, `/skill?ids=…`, `/skill/available` и `/branches/tree`. `AbilityCard` отображает их через `RankedValues` с подсветкой `state.rank`; у магий каталожный `Magic.cost` остаётся числом. Боевой WS DTO `Action.cost?: number` — отдельный контракт: `ActionService.toObject(name, learnedRank)` выбирает одну стоимость изученного ранга, а `SkillConstructor` списывает соответствующий `cost[rank - 1]`. Это не `bonusCost` (бонусы за изучение) и не `proc` (процент хода).
3. **Сброс умений (Респек)**:
   - Описанный в проекте полный сброс умений и физических веток с возвратом бонусов **не реализован**. `MagicService.resetMagics` очищает только магии и магические ветки, физические специализации сохраняет; HTTP-маршрута сброса магий нет.

## 7. Инфраструктура и паттерны боевых умений

### 7.1. Расширения конструктора умений (`SkillConstructor`)
1. **Поддержка разрешённых типов оружия (`weaponTypes`)**:
   - `SkillArgs.weaponTypes?: string[]` передаётся в конфигурацию умения (например, `weaponTypes: ['range']` для выстрелов лучника).
   - `fitsCheck()` вызывается в базовом методе `cast()` до списания энергии и расчёта шанса. Если у инициатора в руках нет оружия подходящего типа, выбрасывается `new CastError('NO_WEAPON')`.
   - Хелпер `checkWeapon(initiator = this.params?.initiator): boolean` используется для проверки оружия в последующих боевых хуках (`onBeforeDamageDeal`, `onDamageDealt` и т.д.).
2. **Автоматический расчёт уровня и эффекта**:
   - `getChance()` и `getCost()` автоматически получают уровень умения персонажа: `initiator.getSkillLevel(this.name) || 1`.
   - Хелпер `getEffect(initiator = this.params?.initiator): number` возвращает значение эффекта для текущего уровня скилла персонажа (`this.effect[lvl - 1]`).

### 7.2. Модификация урона в `BaseActionStatus`
Вместо громоздких мутаций статуса действия разделены два специализированных метода:
- **`mulEffect(multiplier: number)`**: масштабирует общий урон действия (умножает все части урона в `#effectParts`, либо `status.effect`, если части не заданы). Применяется для процентных модификаторов всего урона (например, `aimedShot` множит весь урон выстрела на `1.25..1.5`).
- **`mulEffectPart(effectType: EffectType, multiplier: number)`**: умножает исключительно конкретную составляющую урона (например, удвоение только физического урона при критическом ударе в `criticalStrike`, не затрагивая стихийный урон ядом или огнём).

### 7.3. Хелпер проверки причин срыва действий (`hasReasonActionType`)
Файл: `server/arena/Constuructors/utils/index.ts`
Функция `hasReasonActionType(reason, ...actionTypes)` безопасно определяет, вызван ли срыв действия конкретными механиками (например, `dodge`, `shieldBlock`, `miss`), корректно обрабатывая строковые константы ошибок (`BreaksMessage`), одиночный объект `SuccessArgs` или массив `SuccessArgs[]`. Используется в `onCastFail` для прозрачного обхода защитных эффектов (например, `aimedShot` игнорирует уклонение цели).

### 7.4. Механика «Выстрела в колено» (`CripplingShot`)
Умение `CripplingShot extends Skill` объединяет селф-бафф стрелка и дебафф цели без избыточных внешних классов:
- **`onBeforeDamageDeal(ctx, action)`**: сбивает текущую увёртку цели при физ. атаке оружием дальнего боя (`target.affects.removeEffectsByAction('dodge')`).
- **`onDamageDealt(ctx, action, value)`**:
  - Сразу снижает ловкость цели на текущий раунд через `this.onCast(target, value)`.
  - Вешает `target.affects.addLongEffect` на 2 раунда с хуками `onCast` и `onBeforeAction`.
- **`onCast(target, value)`**: вызывается движком боя (`EngineService`) в начале каждого раунда в стадии `cripplingShot`, повторно срезая ловкость цели после межраундового сброса статов в `StatsService.refresh()`.
- **`onBeforeAction(actionCtx, action, affect)`**: если цель пытается кастовать `dodge`, создаёт контекст `this.createContext(affect.initiator, target, game)` и выбрасывает `new CastError(this.getSuccessResult(this.context))`, срывая уворот и выводя в боевой лог понятную причину срыва.

### 7.5. Унифицированный пайплайн проверки пассивных навыков (`PassiveSkillConstructor.canTrigger`)
Для устранения дублирования бойлерплейта в пассивках (`fieldMedic`, `huntersMark`, `markedShot`, `momentum`, `ricochet`, `staticProtect`) метод `canTrigger` объединяет все необходимые проверки:
```typescript
canTrigger(ctx: BaseActionParams, action?: BaseAction): boolean {
  if (!this.checkAction(action)) return false;       // проверка actionTypes (phys, heal...)
  const { initiator } = this.createContext(ctx.initiator, ctx.target, ctx.game).params;
  if (!this.checkWeapon(initiator)) return false;    // проверка weaponTypes (range, chop...)
  if (!this.isActive(initiator)) return false;       // проверка наличия изученного ранга
  if (this.skipChance) return true;                  // пропуск шанса (гарантированный триггер)
  return this.checkChance(this.context);             // бросок вероятности (1d100 <= chance)
}
```

### 7.6. Клонирование действий и хук завершения каста (`cloneAction` & `onAfterCast`)
Для мульти-атак и вторичных действий (например, второй стрелы в `doubleShot`):
- **`BaseAction.cloneAction(): this`**: создаёт поверхностную копию с тем же прототипом через `Object.assign(Object.create(Object.getPrototypeOf(this)), this)`, без вызова конструктора. Вложенные объекты изначально общие; `createContext()` при новом `cast()` создаёт отдельный контекст. Это позволяет задать копии `isAffect = true` и вызвать `cast()` на вторую цель со смасштабированным `proc`, не заменяя контекст основной атаки.
- **`BaseAffect.onAfterCast` и `PlayerAffects.onAfterCast`**: хук, вызываемый в конце `BaseAction.next()` после фиксации результатов первого действия:
  ```typescript
  context.initiator.affects.onAfterCast(context, this);
  ```
  В `doubleShot` это позволяет зарегистрировать отчёт второго выстрела в раунде (`recordOrderResult(actionClone.getSuccessResult())`) сразу после завершения основной атаки.

### 7.7. Управление контекстом (`BaseActionContext`)
- **`overrideTarget(target: PlayerService)`**: задаёт цель через приватное поле `#overridedTarget` (без прямой перезаписи `params.target`).
- **`clone()`**: возвращает клон контекста с текущей целью (`this.cloneWith(this.target)`).
